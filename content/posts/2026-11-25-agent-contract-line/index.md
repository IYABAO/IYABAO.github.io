今天早上七点二十六分，生产巡检脚本跑完，倒数几行里有这么一行：

```text
RESULT: SKIPSPLIT = design>=7/unresolved<=3/sum_exact=1/threshold_untouched=1/failchain_intact=1/c5=12/verifiers_repinned>=1/verdict=Y
```

这行不是人写的总结，是脚本给自己判的卷子。七个字段，每个字段背后都是一次真实计算：设计性跳过的条数、消歧后应核未核的条数、三和恒等式是否自洽、9-AUDIT 的阈值字面是否还在、`trueMissing → FAIL` 这条链路是否还在、有效覆盖段数、两个下游验器的 pin 是否同步。任何一个字段不过，末尾那个 `verdict` 就自己变成 N，不需要谁记得去改它。

对照一下大多数脚本的收尾：`Write-Host "巡检完成"`。信息量等于零，而且永远不会失败。

## agent 撒谎不是道德问题，是数据结构问题

我这半年带几个 agent 做日常运维，最耗精力的不是它们干不完活，是它们干完之后那句话不可信。归纳下来三种形态，跟模型聪不聪明没关系：

- **交结论不交读数。** 「已修复」「已验证通过」「全部绿」。你追问一句「哪个数」，它才开始现算。
- **交读数不交口径。** 「命中 0 条」。命中的是什么模式？分母是多少？窗口多大？这三样缺一个，0 就可以是「真的没有」也可以是「正则写错了」。
- **交口径不交失败路径。** 只打印成功分支的那半句。失败分支要么不写，要么写了也没人走到。

三种形态的共同点是同一个：**最终结论是一个写死的字符串**。它和实测结果之间没有强制映射。模型今天状态好，写「通过」；状态差，也写「通过」——因为「通过」是它想让你看到的东西，不是它算出来的东西。

所以解法不在提示词里。「你要诚实」「不许谎报」这类约束，最多管到它愿不愿意承认失败，管不到它有没有能力发现失败。真正管用的是收尾那一行：把结论从**叙述**改成**推导**。

## 契约行的三条硬规矩

我叫它「契约行」，格式固定成 `RESULT: <名字> = <字段>/<字段>/.../verdict=Y|N`。要成立，得同时满足三条：

1. **末行固定前缀。** `RESULT:` 开头，一行说完。抓取端不用理解上下文，`tail -1` 就能取到结论，索引脚本、日报、看板全按同一套解析。
2. **每个字段带实测来源。** 字段值要么是当轮实算的计数，要么是从被测文件里读出来的字面匹配结果。不许出现「大概」「应该」「已确认」。
3. **verdict 由字段布尔与推导，代码里不准出现 `verdict=Y` 这个字面量。** 这是最容易被绕过的一条，也是最关键的一条。

落到代码上大概是这样：

```powershell
# 每个字段先算成 0/1 或固定文本，绝不提前拼结论
$designOk   = if ($cStat.designSkip -ge 7)      { 'design>=7' }  else { 'design<7' }
$unresOk    = if ($cStat.unresolvedSkip -le 3)  { 'unresolved<=3' } else { 'unresolved>3' }
$sumExact   = if ($tripleSum -eq $declTotal)    { 'sum_exact=1' } else { 'sum_exact=0' }
$repinOk    = if ($vRepinned -ge 1)             { 'verifiers_repinned>=1' } else { 'verifiers_repinned=0' }
$threshold  = if ($infoSrcTxt -match '\$win24\s*-gt\s*30') { 1 } else { 0 }

# verdict 只有一个出口：七项全真才是 Y
$verdict = if ($designOk -eq 'design>=7' -and
               $unresOk -eq 'unresolved<=3' -and
               $sumExact -eq 'sum_exact=1' -and
               $threshold -eq 1 -and
               $failChainIntact -eq 1 -and
               $c5eff -eq 12 -and
               $repinOk -eq 'verifiers_repinned>=1') { 'Y' } else { 'N' }

Write-Host ("RESULT: SKIPSPLIT = {0}/{1}/{2}/threshold_untouched={3}/failchain_intact={4}/c5={5}/{6}/verdict={7}" -f `
    $designOk, $unresOk, $sumExact, $threshold, $failChainIntact, $c5eff, $repinOk, $verdict)
```

注意 `c5=12` 里的 12：它不是常量，是本轮从巡检结果集里数出来的有效覆盖段数。阈值 30 也不是从参数里读的，而是拿正则去生产脚本源码里匹配 `$win24 -gt 30` 这七个字符——匹配到才算「阈值没被偷偷改大」。这两个字段防的是同一件事：**别把判据本身改成能过关的样子。**

第三项规矩还有一层意思：字段之间必须互相约束。`sum_exact=1` 验的是「已核 + 设计性跳过 + 应核未核 == 声明总数减历史条目」。哪天某个计数的口径漂了，这个等式立刻不成立，verdict 掉 N。第一版我没写这条恒等式，只验了两项相加等于旧的单一 skip 计数，结果它照样吐 Y——我当时差点就收了。补上之后才发现口径对不齐。**契约行唯一不可替代的价值，就是它能自己发现「我刚才判错了」。**

## 反例：一个永远只能打印 Y 的脚本

我也写过这种东西：

```powershell
$fails = @()
# ……一堆检查，每项都只 Write-Host 一行提示，谁也不往 $fails 里塞
if ($fails.Count -eq 0) {
    Write-Host "RESULT: CHECK = verdict=Y"
} else {
    Write-Host "RESULT: CHECK = verdict=N"
}
```

形式上它有 verdict，语义上它只有一种可能的输出：Y。因为 `$fails` 从声明那一刻起就是空的，没有任何代码路径能让它非空。它有 Y 的形状，没有 Y 的语义。

这比不打印更坏。不打印的东西，人还会去查；打印了 `verdict=Y` 的东西，人直接信。一个只会说 Y 的检查，等于给后面所有人发了一张免检通行证。

识别方法很土，也不需要聪明：**把被测对象弄坏，看它会不会变 N。** 改一个字节、删一个文件、把阈值从 30 改成 29，verdict 还是 Y —— 那这行就是装饰品，不是契约。我现在验收任何带 verdict 的脚本，固定加一步「注入必然失败」：故意破坏一个输入，确认 N 真的出现，再还原。出不来 N 的，按没有契约行处理。

## 三次改版，pin 漂了两次

今天这个巡检脚本改了三次，字节数一路是 225,825 → 228,758 → 230,793。改的都是判据逻辑：跳过分列、sandbox 同名消歧、9-AUDIT 的超时清洗口径。

问题出在下游。有两个验器是拿生产脚本的 SHA 当锚的，它们要证明的命题很窄：「我验的是现在这份文件，不是三小时前那份」。脚本一改，SHA 就变，pin 就过期。这时候验器里的 `prod_untouched` 会直接归 0，而不是打一行警告继续跑。

```text
RESULT: GLUELAND = slices=3/total_violations=0/scope_proved=1/prod_untouched=1/verdict=Y
RESULT: FAILDIGEST = segments=92/detail_linked=89/seg11_ok=1/prod_untouched=1/verdict=Y
```

这两行是重新 pin 之后才回来的。`prod_untouched=1` 的含义窄得可怜：验器读到的 SHA 等于当前生产脚本的 SHA。它不证明逻辑对，只证明「我验的对象是这一份」。少了这一步，一份凌晨三点的全绿报告可以原封不动拿去交中午的差，而且没人看得出来。

主契约行里也留了对应字段：`verifiers_repinned>=1`。算法是把两个验器里的 pin 正则抓出来，跟本轮自算的 SHA 逐字比对，匹配数至少一个才算过。这个字段存在的唯一理由，就是让「我忘记重新 pin」这件事自动变成 N，而不是等着谁在群里问一句「你 pin 了吗」。

说起来有点讽刺：防 agent 撒谎的机制，自己也得防自己撒谎。

## 只报清洗后的 30

今天还收拾了一个审计段的老毛病。它统计 24 小时窗口里的超时记录，规则是 `≤30` 过关。改造前它只打印清洗后的数：

```text
WINDOW24H_TIMEOUT=30  THRESHOLD=30
```

看着刚好压线。实际上原始值是 34，中间有 4 条被清洗规则豁免掉了。现在同一行必须把 RAW 一起打出来：

```text
[9-AUDIT][AUDIT9FIX] WINDOW24H_TIMEOUT_RAW=34 CLEARED=4 RIDS=73152d75,57f6aef6,e7cf4742,25548073 WINDOW24H_TIMEOUT_CLEARED=30 RUN_NOW=2026-11-25 07:26:56
```

那 4 条豁免是对的还是错的？可能是对的，规则本来就是为它们写的。但只要读者看不到 34，就没法判断这 4 条到底是合理豁免，还是为了让数字落到 30 而临时放宽的口子。**清洗是允许的，隐藏清洗是不允许的。**

这条可以推广成一句话：任何经过变换的数字，变换前后都要可见。平均值要带样本数，命中率要带分母，去重后的计数要带去重前的，扣掉豁免的要带豁免前的。只留一个漂亮的终值，等于把判断权从读者手里拿走。

## 代价，以及为什么还是划算

老实说，写一行像样的契约行，力气够写五句「已完成」。字段要真算，阈值要真从被测对象里取，失败路径要真存在，还得有人去破坏一次确认它会红。

换来的是三件事：

- **交接不用再靠信任。** 判方拿到的不是一个结论，是一组能复算的字段。不一致的地方当场就能指出来，不用先吵「你是不是又谎报了」。
- **回归是自动的。** 判据逻辑一改，pin 一漂，verdict 自己变 N。不需要谁记得「改完要重跑验器」这条口头纪律。
- **失败信息有结构。** 是 design<7 掉的，还是 repin 掉的，一眼能看出来。这比「巡检失败」四个字有用得多。

反过来，不做这件事的成本我算过：一周里至少三次，我要花半小时以上去核一个「已完成」到底完成了没有。半小时不多，但它是重复的、每天都会来的，而且它消耗的是对人的信任额度。

## 三个能直接抄走的动作

不用一次上七个字段。从最小可用开始：

1. **给每个会产出结论的脚本加末行契约。** 先只写三个字段：一个实算计数、一个阈值字面匹配、一个 verdict。代码里禁止出现 `verdict=Y` 这个字面量。
2. **提交前做一次「弄坏它」测试。** 改一个字节或删一个输入，确认 N 会出现，然后还原。出不来 N 的，说明字段和结论之间没接上。
3. **所有变换过的数字，原始值和终值同行打印。** 这一条不需要写代码，改一行 `Write-Host` 就行，收益最快。

三个动作里，第二个最容易省，也最不该省。前两个字段可以慢慢补，但一条从来没红过的契约行，跟一句「已完成」是同一种东西——只是长得更像证据。
