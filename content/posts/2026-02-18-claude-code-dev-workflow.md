# Claude Code 提效 40%：我们的 AI 辅助研发规范

2025 年我们团队全面引入 Claude Code 辅助研发，三个月后统计：核心模块交付效率提升约 40%，生产环境 0 故障。但说实话，**效率提升不是工具给的，是规范给的**——没有规范，AI 编程工具只会快速产出垃圾。

## 一、先泼冷水：什么场景别用 AI 写

| 场景 | 结论 | 原因 |
|---|---|---|
| 核心账务/资金逻辑 | ❌ 人写 | 出错代价极高，AI 理解不了业务边界 |
| 新框架探索（无人验证过） | ⚠️ 辅助 | AI 训练数据可能没有该框架，幻觉率高 |
| 遗留系统改一处动全身 | ⚠️ 人主导 | AI 看不到全局依赖 |
| CRUD / 样板 / 迁移 / 重构 | ✅ AI 主力 | 模式成熟、可验证 |
| 测试代码 / 文档 / 脚手架 | ✅ AI 主力 | 量大且质量可自动校验 |

**原则：AI 写"可验证的重复劳动"，人写"不可逆的高风险"。**

## 二、任务规范：怎么把任务交给 AI

### 1. 任务拆分最小化

一条任务只做一件事：

```
❌ 帮我重构简历模块，顺便加个搜索
✅ 任务：把 resume_service.go 的 GetList 拆分为 Query 和 Count 两个方法，保持行为不变
```

**AI 任务越小，可控性越高**。我们规定 AI 任务单次改动文件 ≤ 5 个，超过就拆。

### 2. 上下文给足

AI 写代码前必须知道：

```
1. 技术栈与目录结构（项目 README + AGENTS.md）
2. 现有代码风格（找 2-3 个范例文件）
3. 验收标准（测试怎么写、什么算完成）
4. 明确禁止（不许动的文件、不许引入的依赖）
```

**AGENTS.md 是团队 AI 协作的核心文件**：build 命令、测试命令、目录约定、代码风格全写进去，每个 AI 任务自动继承。

### 3. 验收标准写进任务

```
验收：
- 单测通过：go test ./resume/... -run TestGetList
- 代码风格：gofmt + golangci-lint 无 error
- 行为不变：旧接口回归通过
```

## 三、工作流：人机协作闭环

```
人：拆任务 + 定验收
  ▼
AI：实现 + 自测
  ▼
人：代码审查（重点：业务逻辑、边界、安全问题）
  ▼
AI：按 review 意见修改
  ▼
人：合并 + 发布
```

**关键：AI 写完必须自测**——Claude Code 里直接让它跑测试、跑 lint、跑构建，不过不许提交。**AI 的"完成"必须可验证**，不是"代码写完了"。

## 四、代码审查清单（人必看，AI 常错的地方）

AI 写代码的高频错误，review 时重点看：

```
1. 安全：SQL 注入、XSS、越权（AI 常忽略权限校验）
2. 边界：空值、超长、并发竞争（AI 测试用例经常漏）
3. 依赖：擅自引入新库（必须禁止——依赖是有成本的）
4. 错误处理：吞错误、裸 panic（AI 倾向"看起来对"）
5. 性能：N+1 查询、循环内 IO（AI 不感知真实数据量）
```

**我们 40% 的提效里，有一半来自"AI 写初稿 + 人只看关键点"的配合**——人从"写全部代码"变成"写 20% 核心 + 审 80% 初稿"。

## 五、禁止事项（写在团队规范里）

1. **禁止 AI 碰生产配置**：DB 密码、token、环境变量——只允许人改
2. **禁止 AI 提交未验证代码**：测试不过不 push
3. **禁止 AI 引入新依赖**：必须人确认（许可证、体积、维护状态）
4. **禁止 AI 重构"没有测试覆盖"的代码**：先补测试，再让 AI 动
5. **禁止盲信 AI 的"完成"**：只认验证结果，不认口头汇报

## 六、效果数据

| 指标 | 引入前 | 引入后 3 个月 |
|---|---|---|
| 核心模块交付周期 | 4.2 天/模块 | 2.5 天/模块（-40%） |
| 单测覆盖率 | 55% | 78%（AI 补测试快） |
| 生产故障 | 2 次 | 0 次 |
| 重构模块交付 | 20+ 个 | （同期） |

## 七、给团队的落地建议

1. **先挑 2 个模块试点**，跑通"任务→AI→review"闭环，别一步全推开
2. **AGENTS.md 先写好**：没有项目规范，AI 就是脱缰野马
3. **review 是底线**：AI 代码必须人审，这条永远不能省
4. **统计验证**：3 个月后对比交付数据，用数据决定推不推全组

## 总结

AI 辅助研发的公式：

> **提效 = 任务边界 × 上下文质量 × 验证闭环 ÷ 审查松懈**

1. 任务拆小，验收写清
2. 上下文给足（AGENTS.md 是地基）
3. AI 自测 + 人审查，双保险
4. 高风险场景人写，可验证场景 AI 主力

**工具谁都买得到，规范才是团队壁垒。** 我们 40% 不是 Claude Code 给的，是这套协作方式给的。
