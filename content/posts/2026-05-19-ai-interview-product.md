# AI 面试模拟器：商业化产品的技术拆解

Demo 和产品之间隔着一整条深水区：**流程不失控、流式不卡、计费不错、数据不泄**。这篇文章拆解 AI 面试模拟器从 0 到商业化的技术架构——重点是"能收费"背后那些不性感但决定成败的环节。

## 一、产品形态

```
用户 → 选择岗位/简历 → 开始 AI 面试
  → AI 面试官提问（流式输出）
  → 用户语音/文字回答
  → AI 追问/换题/评分
  → 结束 → 面试报告（评分 + 建议）
  → 报告查看 → 会员付费解锁深度报告
```

## 二、核心架构

```
┌─ 客户端（Web/App）
│    ├─ 语音采集（WebRTC/录音）
│    └─ 流式渲染（SSE 逐字显示）
│
├─ 网关层（One-API 兼容）
│    ├─ 多模型路由（成本/质量平衡）
│    └─ 计费计量（按 token 记账）
│
├─ 业务层（Go 微服务）
│    ├─ 会话服务（状态机：开场→提问→评分）
│    ├─ 语音服务（ASR 转文字）
│    └─ 报告服务（评分 + 生成报告）
│
└─ 数据层
     ├─ 简历数据（RAG 检索）
     ├─ 会话记录（可回放）
     └─ 计费流水（对账）
```

## 三、技术关键点

### 1. 流程控制：状态机（前文详述）

```
[START] → [INTRO] → [Q1] → [A1 判定] → [Q2] → ... → [END] → [REPORT]
                     ↑          │
                     └── 追问 ←─┘（回答质量低 → 追问 1 次）
```

**为什么必须状态机**：AI 面试的"越级"是产品事故（问第 3 题的时候提到了"刚才第 5 题的内容"）。**状态机锁死流程**，LLM 只在状态内生成。

### 2. 流式响应：SSE 工程

```go
// Go：SSE 流式转发（自研代理，替代 PHP+Socket）
func streamHandler(w http.ResponseWriter, r *http.Request) {
    flusher, _ := w.(http.Flusher)
    w.Header().Set("Content-Type", "text/event-stream")
    // 从 LLM 拿流 → 逐块转发给客户端
    for chunk := range llmStream(r.Context()) {
        fmt.Fprintf(w, "data: %s\n\n", chunk)
        flusher.Flush()
    }
}
```

**工程要点**：

```
✅ 心跳（注释行）防中间层超时断开
✅ 客户端断线 → 服务端取消（context 取消）
✅ 背压：LLM 生成快、网络慢 → 缓冲控制
✅ 错误事件类型化（error/retry 区分）
```

**指标**：TTFT < 500ms，首字即出，用户"看见它在打字"。

### 3. 计费闭环

```
流程：会话开始 → 计量（token/时长/次数）→ 会话结束 → 记账 → 扣费/额度
```

**关键**：

```
✅ 计量在网关层（不信任业务层统计）
✅ 对账：网关流水 vs 业务订单，日对账
✅ 免费额度：体验卡（3 次/天）
✅ VIP：无限次 + 深度报告
✅ 防刷：单用户会话上限、风控（异常高频）
```

**计费是"信任基建"**：算错一分钱，用户信任就崩。

### 4. 数据安全

```
✅ 简历数据 RAG 检索 + 权限过滤（只能看自己的）
✅ 会话数据隔离（用户 A 不能看用户 B）
✅ 语音流加密传输、ASR 后即弃（不留原始音频）
✅ 全链路审计（谁、何时、调了什么）
```

### 5. 评测迭代

```
离线：评测集（流程正确性、问题质量、评分准确）
在线：完成率、追问率、付费转化率、投诉率
A/B：换模型/Prompt/评分算法都要实验
```

## 四、商业化验证：三个关键指标

| 指标 | 含义 | 我们的数据 |
|---|---|---|
| **完成率** | 开始面试 → 完整走完的比例 | 72% |
| **付费转化** | 面试完成 → 解锁报告的占比 | 8-12% |
| **NPS/复购** | 用户愿不愿意再来/推荐 | 正向 |

**产品迭代优先级**：先提完成率（体验差没人付费）→ 再提转化（报告价值）→ 再做复购（内容沉淀）。

## 五、踩坑记录

1. **SSE 被中间层缓冲**：Nginx 没关 buffering → 流式变"等全部完成才出" → `X-Accel-Buffering: no`
2. **语音识别误差传导**：ASR 错了，AI 面试官"答非所问" → 回答回显（用户可改）+ 置信度低时提示
3. **计费时机错误**：会话中扣费（用户中途退出白扣）→ 会话结束才结算 + 异常会话退款
4. **模型换代的回归**：换更强模型，流程反而"越级"了（更聪明 = 更不守规矩）→ 每次换模型跑流程评测集

## 总结

商业化 AI 产品的核心认知：

1. **Demo 看"聪明"，产品看"可控"**：状态机、限流、计费、安全，全是不性感但要命的
2. **流式是体验底线**：TTFT + 逐字渲染 = 用户感知"真 AI"
3. **计费是信任基建**：计量准、对账清、异常可退
4. **商业化指标驱动迭代**：完成率 → 转化率 → 复购

**AI 产品能不能收费，不取决于模型多聪明，取决于"聪明之外的那层工程"有多扎实。**
