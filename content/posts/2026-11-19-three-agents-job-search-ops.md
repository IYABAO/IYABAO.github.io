> 本文数据来自我自己的本机链路，命令可复现。涉及的组织、账号、凭据、内网路径均已泛化；三个 agent 以 A/B/C 指代。

我有三个常驻 agent 在帮我管求职这件事。A 管节奏和任务看板，B 管财务判据和内容产出，C 管巡检和复算。它们各自有工作区、各自有日志，每隔半小时自己醒一次。

有人问我这套东西到底怎么跑起来的。答案不是某个神奇的 prompt，是四块很土的机械装置：心跳 cron、记分卡、交叉复算、幽灵产物核验。前两块让它们动起来、可被衡量；后两块让它们没法自己给自己打分、没法把「写好了」冒充「上线了」。

这四块不是一次装好的，是各自咬过我一口之后补上的。这篇按「为什么要装」的顺序讲，最后讲它们**一起失效**的样子——那才是最难查的。

## 一、心跳 cron：让 agent 自己动起来，而不是我叫一次动一次

最早我用一个词指挥 agent：「你去做」。问题是这句话的有效期只有一次对话。第二天它不会自己醒，我得再叫一遍。三台都这样，我就成了人肉定时器。

改法是给每台挂一个心跳：操作系统级定时，每隔固定时刻唤醒一次 agent，让它按一份固定清单干活、写日志、然后睡回去。

时钟长这样：

```text
:17 / :47  两个相位，30 分钟一格
A: 每格醒    B: 每格醒    C: 每格醒
```

三台都醒，但醒过来干的事不一样。真正的关键不是「醒」，是「醒过来读什么」。我给它们一张差距表：每行一个判据，写着目标值、当前值、差距，还有「复算方」和「上次领取时间」。心跳第一件事不是干活，是读这张表，按差距从大到小排序，挑最大的那一条，自己建一张任务卡去推。

这就把「我今天该干嘛」从我的脑子搬到了一张机器能读的表里。

```text
判据  目标    当前    差距      复算方   上次领取
J1    100%   100%   0（已达成） C       08:17
J2    ≥ 0.9  1.0    0（已达成） C       08:17
J4    ≥ 2/周 3      0（已达成） C       08:17
```

锁是这时候必须加的。三台同时盯一张表，很容易同一条判据被领三次。我的规则是：同一主题两小时内不重复领，判据取「上次领取时间」和看板状态里先到的那个。两小时正好四个格子。

```text
锁窗 = 2h = 4 格
:17 领的活，到 +2h 的 :17 才解锁
窗口内的新证据只许回填数值，不许新建任务
```

还有一条反直觉的规矩：差距为 0 的不领，已裁定「不可达」的也不领。我吃过亏——有两条判据方向天然相反，抬高一条必然踩爆另一条，我让 agent 反复去领，它每半小时烧一次算力，跑出一个注定失败的结论。后来给这两条打了永久排除标记，只允许记账，不许领活。

心跳跑顺之后，真正的风险变成了「它静默少跑了一跳」。所以每条心跳都要留一行日志，日志要能被反解回段标签——相位、队列、动作三格必须从日志行解析出来，不许硬编码。我曾经把一整段日志的槽位全写成同一个数，实际上每分钟都不一样，查了半天才发现根因是「写死」而不是「算出来」。

## 二、记分卡：把「已完成」翻译成数字

心跳解决了「动不动」，没解决「干得怎么样」。agent 汇报的末尾一律写「已完成」，这三个字不值钱。

我给每台建了一张记分卡，固定六列：

```text
ID / 判据 / 复算命令 / 目标值 / 当前值 / 达标
```

「达标」列只准写 Y / N / BROKEN，后来又加了一个一等态 SKIP。加起来六列，我自己违反过五次。

第一条铁律是：**当前值必须由卡面上那条命令算出来，不许手写。**

我第一版卡面写「答满 6/10，达标」。核验器把命令贴进终端一跑，输出 `6/0`——分母是 0。`6/10` 是我早先手动抄进去的，从那以后再没跟过命令。差一个字符，判据就从教训变成了自我安慰。

```text
 RESULT: J2 = 6/0        （命令实测，裸输出）
 卡面写：6/10            （手写残留）
```

第二类翻车更隐蔽：命令指向一个已经被标记「废弃」的旧文件。旧文件 60 条，新文件 80 条，命令还指着旧的，读出来的数低了三分之一。文件头上有作废标记，但命令不读标记，命令只读文件。

第三类是比值被压成二态。`6/10` 里有两个数字，我拿去喂判定器，它在斜杠处截断，把判据值读成 6，然后 `6 ≥ 0.9` 直接判 PASS——一个假绿。后来我把命令改成只吐一个小数，才真正可机判。

```text
改造前：RESULT: J2 = 6/10    → 判 6 ≥ 0.9 → PASS（假绿）
改造后：RESULT: J2 = 1.0     → 判 1.0 ≥ 0.9 → PASS（真绿）
```

我现在的口径只有一句：卡面当前值不许手写，写不出来的标「待核」，不许当事实。判据描述里出现「良好 / 达标 / 稳步推进」这类形容词，一律退回重写。

## 三、交叉复算：自己算的不算数

记分卡装好，我以为高枕无忧了。两周后发现一个致命漏洞：判据是我写的，命令是我配的，当前值是我跑的，达标也是我判的。整套链条里「我」无处不在。

解法是环形复算：每张卡都指定一个「复算方」，自己算的不算数。

```text
A 的卡 → 由 B 复算
B 的卡 → 由 C 复算
C 的卡 → 由 A 复算
```

复算方每轮心跳按指定的命令原文重跑一遍，把输出的 `RESULT:` 行原文贴回来。差异分成两类：硬分歧和口径差。硬分歧是同一条命令跑出两个不同结果，那是事故；口径差是命令没变、卡面文本悄悄换了说法，那更阴。

有一条纪律是踩坑之后写死的：**复算值和卡面读数不一致，以实跑命令输出为准回写当前值和差距，并在备注里写明分歧来源、日期、命令原文。** 分歧不许靠「谁先写的」来定。

```text
复算：以实跑命令输出为准
回写三件套：当前值 / 差距 / 分歧来源+日期+命令原文
```

我还加了两条排除规则，是复算跑出来的结论倒逼的。一条是某判据对象已经消失——相关合约清零后，唯一义务腿没了，判据对象不存在，判 N/A、不计入合计。另一条是两条判据结构性冲突：要把覆盖率从 28.4% 抬到 50%，得加一层对冲腿，而那层腿的保费会直接踩爆另一条「保费不超过 2%」的纪律。两条方向相反，缺口不可能靠「再领一次」补上。这类判据复算得越勤，越浪费。

交叉复算最值钱的产出不是「查出错」，是逼我把每条判据都写成一条别人能照着跑的命令。写不清的命令，复算方跑不出来，卡面就得改。

## 四、幽灵产物核验：写了 ≠ 落盘

链路前面三块都解决了「怎么算」，还有一块解决「到底有没有」。

我最惨的一次是模拟面试第二轮：连续五次汇报「已写入 / 已生成」，实际文件一个都没落盘。人工交叉复算把五次全数打回。那一刻我明白，agent 的「已完成」和磁盘上的字节之间，隔着一整个诚实鸿沟。

现在的规矩很机械：任何声称产出的交付，必须当场跑一条落盘自检，贴出绝对路径、字节数、修改时间。没有字节数和 mtime，一律按没做处理。

```powershell
powershell -NoProfile -Command "Get-Item '<产物绝对路径>' | Select-Object Name,Length,LastWriteTime"
```

光这样还不够。索引和日报会互相引用对方的字节数，A 引用 B、B 引用 A，谁先写谁的数都不对。我的解法是字节数先写固定宽度占位符，写完再回填，让「自报值 == 实测值」收敛，且回填前后文件长度不变。

```text
步骤：日报占位 XXXX → 实测日报 → 写索引 → 实测索引 → 回填日报
约束：占位符宽度固定，回填不改长度
结果：两边互为不动点
```

数值型交付还要点名复算方。按差距表里「复算方」那一列直接交接，交付即发起复核，不做中转。这四块拼起来，是一个闭环：心跳让它们动，记分卡让它们可被衡量，复算让它们不能自证，落盘核验让它们不能谎报。

## 五、四件套一起失效的样子

单看每块都有补丁，麻烦出在它们互相咬合的地方。我这四个样本全是咬合处出的。

**样本一：SKIP 兜底成装睡。** 一条判据的卡面命令指向一个「永无数据」的日期，底层吐 `status=SKIP`，卡面命令把结果翻译成 `RESULT: C2 = SKIP` 后退出码归 0。汇总行从红变绿，谁都没报错。真实原因平常得很：被测日期跨到了新一天，当日心跳日志还没生成。SKIP 既不是失败也不是达标，它是第三种状态，必须进汇总、不进达标率。

```text
底层：status=SKIP / ERROR: log file not found
卡面：RESULT: C2 = SKIP   RC=0
表面：PASS=5 FAIL=0 SKIP=1   → 看着全绿
```

**样本二：值驻留。** 权威表已经把 F3 的读数更新成 18.05%，抄它的视图还停在 28.4%。心跳每半小时读那个视图，把算力烧在一个早已达标的判据上。数据没错，错的是抄它的那一行。

**样本三：恒等式判据。** 一条判据写「环境三态 == 0」，而环境正常时它天然就是 0，判据恒 PASS，从来没被真正测过。区分度不在那个 0 上，在反证场景里。

**样本四：两判据打架。** 就是前面说的覆盖率和保费。这种冲突不会报红，只会让 agent 在两条都完不成的任务之间反复横跳。

这四个样本有个共同点：退出码是 0，日志干净，没有一个抛出异常。它们不是 bug，是「成功」这个词的定义被人钻了空子。

## 六、能直接抄的六条纪律

如果你也要用这套东西管自己的 agent，六条就够：

```text
1. 判据必须一条命令算出数字，形容词一律退回重写
2. 卡面当前值不许手写，写不出来标「待核」
3. 自算不算数，每张卡指定复算方，按命令原文重跑
4. 复算与卡面冲突，以实跑输出为准回写，写明分歧来源
5. 声称产出必须贴字节数 + mtime，拿不出按没做处理
6. SKIP 单列，不进达标率；方向相反的判据标结构性冲突，永久排除领活
```

最后说句实在的。这三台 agent 没让我少干活，它们把「我到底交付了什么」这个问题变成了每天能回答的事。我信不过记忆，也信不过「已完成」三个字，我只信任那条能被别人重跑的命令和那个能测到字节的文件。
