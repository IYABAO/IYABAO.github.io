# AI 时代的架构师：角色升级与能力模型

"AI 都能写代码了，还要架构师干嘛？"——这是 2025 年最常见的疑问之一。我的回答：**AI 让"写代码"贬值，让"做决策"升值**。架构师的角色正在从"技术权威"变成"决策中枢"。

## 一、AI 对工程能力的冲击

```
AI 能做的（正在做的）：
  写 CRUD、写测试、写文档、重构、查 API
  → 这些"执行性"能力快速贬值

AI 做不好的（架构师的价值区）：
  定边界（系统边界、职责边界）
  做取舍（成本/性能/复杂度/时间的权衡）
  建体系（可观测、可演进、可治理）
  管不确定性（需求变化、技术变化、风险）
```

**核心判断**：**AI 解决"怎么做"，架构师解决"做什么和为什么"。**

## 二、架构师能力模型（AI 时代）

### 1. 决策能力（最核心）

```
架构 = 一系列取舍的累积

取舍维度：
  性能 vs 成本（多级缓存 vs 直接查库）
  灵活 vs 简单（微服务 vs 单体）
  快 vs 稳（快速上线 vs 完整测试）
  自研 vs 采购（AI 能力自建还是用现成）

AI 给不了答案的：
  业务优先级（哪个需求最重要）
  团队能力（团队会不会这个技术）
  时间窗口（什么时候必须上线）
```

### 2. 抽象与建模能力

```
✅ 把业务抽象成模型（领域建模）
✅ 把系统拆成边界清晰的模块
✅ 定义接口契约（模块之间怎么协作）
✅ 把"模糊需求"变成"清晰设计"

AI 擅长"在边界内生成"，不擅长"定义边界本身"
```

### 3. 体系化思维

```
✅ 可观测体系（指标/日志/链路）
✅ 质量体系（测试/审查/门禁）
✅ 治理体系（规范/评审/准入）
✅ AI 应用还需要：评测体系、成本治理、安全边界

架构师的核心产出：不是代码，是"让系统长期健康运行的体系"
```

### 4. AI 工程能力（新必修）

```
2026 年架构师的新技能：
  评测体系设计（AI 质量怎么衡量）
  成本治理（token 怎么省）
  Agent 编排设计（流程怎么控制）
  数据飞轮（反馈怎么回流）

用 AI 提效：Claude Code 等工具是架构师的新杠杆
  → 架构师用 AI 快速验证架构方案（原型速度 ×10）
```

## 三、架构师的工作方式变化

```
以前：
  画架构图 → 写核心代码 → 评审别人代码 → 救火

现在（AI 时代）：
  定目标与约束 → 让 AI 生成方案（多个候选）
  → 评估取舍 → 选定方向 → AI 实施 + 架构师审查
  → 建评测/治理体系 → 关注长期健康
```

**提效点**：

```
✅ 方案对比：让 AI 出 3 个方案 + 各自权衡（架构师做决定）
✅ 文档自动生成：ADR（架构决策记录）AI 起草，架构师审
✅ 代码审查：AI 初审（风格/漏洞），架构师看"设计层面"
```

## 四、对资深工程师的启示

```
如果目标是架构师/技术负责人：

1. 深度做决策练习：
   - 每次设计都写"为什么这么选"（ADR）
   - 主动承担"取舍"（别等领导拍板）

2. 建立体系化视角：
   - 不止写功能，想"如何长期维护"
   - 把个人经验沉淀成"团队的规范/体系"

3. 拥抱 AI 工具：
   - 用 AI 提效（原型/文档/审查）
   - 学会"验收 AI 产出"（这是新基本功）

4. 补齐业务理解：
   - 技术决策最终是业务决策
   - 懂业务优先级，才能做对的取舍
```

## 五、AI 时代架构师的核心认知

```
1. 写代码的能力会被 AI 平权，决策能力不会
2. 架构师的产出从"系统设计"变为"决策 + 体系"
3. 会用 AI 是基础，会用 AI 验证决策才是能力
4. 可评测、可治理、可演进 —— 这些"体系"越来越值钱
```

## 总结

AI 时代架构师的角色升级：

1. **从"技术权威"到"决策中枢"**：定边界、做取舍、管不确定
2. **四维能力**：决策、抽象建模、体系化、AI 工程
3. **工作方式变化**：AI 出方案，架构师做选择
4. **心态**：AI 是杠杆，不是对手

**AI 不会取代架构师，会取代"只会写代码的架构师"。** 那些能把模糊变成清晰、把取舍变成决策、把经验变成体系的人，在 AI 时代反而更稀缺。
