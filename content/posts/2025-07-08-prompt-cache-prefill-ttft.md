# Prompt 缓存与预填充：TTFT 优化的工程实践

AI 产品的体验生死线不是总延迟，是**首字延迟（TTFT）**——用户发完问题到看到第一个字的时间。3 秒的 TTFT 用户就流失，500ms 用户觉得"真快"。

TTFT 优化两大杀器：**Prompt 缓存**（重复内容不重新计算）和**预填充（Prefill）**（让模型先想好再开口）。这两个我在 AI 面试产品里都用了，效果显著。

## 一、TTFT 为什么慢

LLM 生成过程：

```
输入（Prompt）→ 逐 token 处理（prefill 阶段）→ 逐 token 生成（decode 阶段）
                  ↑
            TTFT = prefill + 第一个生成 token
```

**问题**：

```
1. 系统提示词 + 历史对话每次都要重新处理（prefill 重复计算）
2. 长 Prompt 的 prefill 可能占 TTFT 的 80%
3. 模型"边想边说"，第一句话可能啰嗦/卡顿
```

## 二、第一招：Prompt 缓存

### 原理

```
Prompt = 系统提示词（不变）+ 历史（渐增）+ 新问题（变化）
                   ↑
          模型服务商缓存"不变的前缀"的 KV
          → 下次相同前缀直接复用，跳过 prefill
```

### 落地

```python
# OpenAI/Anthropic 等主流 API 都支持（自动生效或显式启用）
messages = [
    {"role": "system", "content": SYSTEM_PROMPT},  # 固定前缀
    *history,                                      # 渐增
    {"role": "user", "content": new_question},
]
# 命中缓存：缓存前缀部分不再计费、不再重新计算
```

### 关键设计：把"不变"放前面

```
✅ 系统提示词固定（别动态拼日期/用户名到前面）
✅ 静态知识放前缀，动态内容放后面
✅ 提示词版本控制（改提示词 = 缓存失效，控制频率）

❌ 每轮动态生成系统提示词（前缀每次都变 → 缓存永远 miss）
❌ 把用户消息塞进前缀（完全不可缓存）
```

### 效果

```
缓存命中时：TTFT 降 40-60%，prefill 成本降 80%+
对话场景：第 2 轮起前缀基本命中（只要前缀不变）
```

## 三、第二招：预填充（Prefill）

### 原理

**让模型"先想好，再开口"**：在生成开始前，预填 assistant 的开头，把模型引向正确的回答结构。

```
场景：AI 面试官
预填："基于简历中的『3 年 Go 后端』经历，接下来问："

作用：
  1. 跳过"思考"阶段的废话（不让模型"嗯…让我想想"）
  2. 锁定输出方向（回答结构、语气、立场）
  3. 减少重新生成的轮次（一次说对）
```

### 实现

```python
messages = [
    {"role": "system", "content": SYSTEM},
    {"role": "user", "content": question},
    {"role": "assistant", "content": "基于候选人所述，我的评价是："}  # prefill
]
# 模型从这里继续生成，方向被锁定
```

### 最佳实践

```
✅ 预填回答的开头结构（"我的结论是…"）
✅ 预填关键判断（"该项目 QPS 从 800 提升到 5000+"）
✅ 预填拒绝理由（不该答的："这超出我的范围"）
❌ 预填太长（超过几百 token 效果递减，且浪费）
❌ 预填和系统提示词冲突（会混乱）
```

## 四、组合拳：三层 Prompt + 缓存 + 预填充

我们 AI 面试的最终架构：

```
System（强元规则 + 角色）── 固定 → Prompt 缓存命中
User（每轮问题 + 简历片段）── 变化
Assistant 预填（开场引导）── 锁定输出
```

```
TTFT 效果：
  基线：1.8s（无优化）
  + Prompt 缓存：800ms（缓存命中）
  + 预填充：650ms（更少重新生成）
  + 模型优化（更快的模型）：450ms
```

## 五、其他 TTFT 优化手段

| 手段 | 原理 | 效果 |
|---|---|---|
| **Prompt 缓存** | 复用前缀计算 | 40-60% |
| **预填充** | 锁定输出方向 | 减少返工 |
| **流式输出** | 首字即出，边生成边展示 | 感知提升 50%+ |
| **小模型前置** | 简单问题走快模型 | 场景性 |
| **并发预取** | 预估用户问题预生成 | 高级，复杂 |

**流式输出（SSE）是必做项**：TTFT 3 秒但流式显示，用户感知是"它在打字"；TTFT 0.5 秒但白屏 10 秒，用户感知是"卡死了"。**感知 = 首字时间 + 流式节奏。**

## 六、踩坑记录

1. **缓存前缀污染**：系统提示词里拼了时间戳 → 每 60 秒缓存失效一次 → 时间类内容放 User 层
2. **预填过度**：预填了完整的回答 → 模型只补充最后一句 → 回答失去自然性 → 预填 20-50 token 足够
3. **缓存计费误解**：缓存命中省的是 prefill 计算，不是全部费用 → 看账单要分 prefill/output
4. **缓存与服务商绑定**：切换模型/服务商缓存失效 → 设计上别依赖缓存，当"白赚"的优化

## 总结

TTFT 优化的核心认知：

1. **TTFT 是体验生死线**：流式 + 首字快 = 用户觉得快
2. **Prompt 缓存是地基**：前缀固定、静态在前，命中率决定收益
3. **预填充是方向盘**：锁定输出方向，减少返工
4. **组合拳**：缓存 + 预填 + 流式 + 合适模型

**AI 产品的"快"，不是生成快，是"开口快"**。首字时间 + 流式节奏，比总耗时更能决定用户感受。
