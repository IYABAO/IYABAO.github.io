# Fluxio 信息流聚合：RSS、快照与本地优先的架构

Fluxio 是一个信息流聚合工具：横向切换多个信息源（新闻、博客、社区），一键收藏到 Obsidian。这篇文章是它的架构决策记录——尤其是三个核心取舍。

## 一、需求与定位

```
核心场景：
  把多个信息源（网页 URL 列表）放进一个"信息流"
  左右横滑切换来源
  看到好内容 → 一键收藏（存内容全文，不只是链接）
  收藏同步到 Obsidian（内容入库，可离线读）

定位：本地优先的个人信息中枢
```

## 二、架构总览

```
┌─ 客户端（Flutter）
│   ├─ 信息流页面（横向切换）
│   ├─ 详情页（WebView / 快照渲染）
│   └─ 收藏夹（全文 + 样式）
│
├─ 本地服务（收件箱 API，127.0.0.1:8730）
│   ├─ 浏览器扩展/分享入口 → 收藏入库
│   └─ 内容快照服务（URL → 正文快照）
│
├─ 本地存储
│   ├─ SQLite（收藏元数据 + 全文）
│   └─ 文件系统（快照 HTML/图片）
│
└─ 同步（Obsidian 双向）
    ├─ 导出：收藏 → Markdown 文件
    └─ 导入：Obsidian 笔记 → 信息流
```

## 三、核心决策 1：WebView 还是快照

**场景**：信息流里点开一篇文章 → 详情页。

```
方案 A：直接 WebView 加载原 URL
  优点：原站原样、零解析
  缺点：依赖原站可用、被反爬拦截、内容会被改/删

方案 B：抓取正文 → 本地快照渲染
  优点：稳定、离线可读、收藏的是"当时的完整内容"
  缺点：样式有损、实现复杂
```

**决策**：**默认快照，WebView 兜底**：

```
详情页 = 本地快照（抓取时保存的 HTML）
快照失败/想上原站 → 一键"在浏览器打开"
收藏 = 快照全文（不是链接）
```

**为什么收藏必须存全文**：链接会失效、内容会被改、离线要能读——**收藏的语义是"保存这一刻的内容"**，不是"记住一个地址"。

## 四、核心决策 2：本地优先

```
❌ 云端架构：所有收藏先上云，再同步设备
✅ 本地优先：数据先落本地，同步是可选的增值

本地优先的收益：
  隐私（内容不出设备，除非你选同步）
  速度（本地 SQLite 毫秒级）
  稳定（没网也能用）
  可控（数据是文件，可备份可迁移）
```

**实现**：SQLite 本地库 + Obsidian 目录同步（Markdown 文件）。

```
收藏流程：
  扩展/分享 → 本地收件箱 API → 抓取快照 → 写 SQLite + 写 Markdown 文件
  → （可选）同步到 Obsidian vault
```

## 五、核心决策 3：收藏进 Obsidian 的格式

**Obsidian 收藏的必须是"内容详情"，不是链接**：

```markdown
---
title: "AI 面试产品的幻觉治理"
source: "https://xxx.com/article/123"
collected: "2026-03-03 10:00"
tags: [AI, 面试]
---

# AI 面试产品的幻觉治理

（正文全文，图片本地化）

> 来源：[原文链接](https://xxx.com/article/123)
```

**关键点**：

```
✅ 正文全文（不是摘要）
✅ 图片本地化（不然 Obsidian 离线看不到图）
✅ 元数据 frontmatter（可检索/可统计）
✅ 原文链接保留（可溯源）
```

## 六、收件箱：任何 App 都能"分享进来"

**浏览器扩展（MV3）**：

```
Chrome 扩展：右键"分享到 Fluxio" → POST 到 http://127.0.0.1:8730/inbox
```

**移动端分享**（规划）：系统分享菜单 → 调本地服务。

```
收件箱 API（127.0.0.1:8730）：
  POST /inbox       接收分享（URL/标题/正文/来源）
  GET  /items       列出收藏
  GET  /items/:id   详情
  POST /sync/obsidian  触发 Obsidian 同步
```

**本地 API 的安全**：绑定 127.0.0.1，token 校验，防局域网滥用。

## 七、技术栈与取舍

| 层 | 选择 | 原因 |
|---|---|---|
| 客户端 | Flutter（Windows 先，移动后） | 一套代码多端 |
| 本地服务 | Dart（同语言） | 减少栈 |
| 存储 | SQLite + 文件 | 本地优先标配 |
| 抓取 | 无头浏览器 / HTTP 解析 | 按站点适配 |
| 同步 | Markdown 文件 | Obsidian 原生格式 |

## 八、踩坑记录

1. **快照样式丢失**：抓的 HTML 缺 CSS → 渲染"裸奔" → 内联关键样式 + 阅读模式兜底
2. **图片外链失效**：快照只存了正文没存图 → 图片本地化（下载到本地目录）
3. **收件箱 API 与浏览器安全**：网页 JS 不能直接调本地 API → 用扩展（有权限）+ CORS 限制
4. **Obsidian 同步冲突**：双端同时写同一文件 → 文件按时间戳命名 + 冲突保留

## 九、路线图

```
V1（已完成）：Windows 客户端 + 信息流 + 快照收藏 + Obsidian 同步
V2：移动端（Taro 小程序 + Flutter）
V3：多设备同步（可选云端）
V4：AI 摘要（收藏自动打标签/摘要）
```

## 总结

Fluxio 的核心认知：

1. **收藏存全文不存链接**：内容会失效，快照才是"收藏"
2. **本地优先**：数据在自己手里，同步是增值不是依赖
3. **收件箱模式**：任何 App 分享进来 = 统一入口
4. **Obsidian 同步用 Markdown**：原生格式，双向不折腾

**信息流工具的本质：把"信息经过"变成"信息资产"**。快照 + 本地 + 可同步，让每次阅读都有沉淀。
