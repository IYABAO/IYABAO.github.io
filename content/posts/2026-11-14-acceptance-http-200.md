内容线立了一条硬规矩：**一篇 = 一条任务，闭环到上线**。验收标准写得很具体——线上可访问链接，HTTP 200，不是「写了多少字」。

这条规矩不是拍脑袋立的，是被一次盘点打脸打出来的。那次盘点我数了两本账：字数报表很漂亮，本周写了好几篇、合计上万字；线上账号里，这个周期新增加载出来的文章，数量对不上。有稿子写完了躺在本地目录里，没有发布配置、没有推送，线上根本没有这个东西。报表说的是「写了」，但「写了」这个动词，在整条流程里停在了第一步。

这篇讲我把验收标准钉到 HTTP 200 之后，整条发布链路发生了什么。核心结论一句话：**验收标准定在链路哪一环，交付物就停在那一环。**

## 字数验收量的是库存，不是交付

先说清楚交付物的定义。一篇博客的交付物不是 markdown 文件，是**一个能从公网打开的 URL**。从「写完稿」到「URL 可访问」，中间隔着五道关：

```text
脱敏 → 发布配置 → 构建自检 → 推送 → 部署验证
```

字数在第一道关之前就量完了。后四道关它一概看不见。所以字数验收下出现了一种特别舒适的假象：报表数字每周都在涨，线上纹丝不动。稿子躺在本地，每一道关都没走，但「写了三千字」这句话是真的——验收量到的东西存在，交付要的东西不存在。

这不是执行者偷懒，是验收标准把交付物的定义写歪了。你按字数验收，团队就会优化字数；你按「可访问」验收，团队才会去打通那四道关。指标是什么，交付物就是什么——这不是态度问题，是定义问题。

## 五道关，每道关躺着一个真实的坑

把验收钉到 HTTP 200 之后，我回头把五道关各写了一条红线。写完发现，这些红线没有一条是提前设计出来的，全是真实事故的尸检结论。**红线清单不是纪律，是尸检报告。**

### 关一：脱敏，grep 0 匹配是硬门槛

技术复盘写多了，最容易泄的底不是密码，是上下文：真实公司名、内网 IP、令牌、行业专属词——懂行的人看到几个专属词就能反推出你在哪个行业、哪家公司。所以脱敏清单分了六类：公司身份、真实索引名、内网地址与凭证、真实客户名、行业专属词、内部路径。

自检是一条命令的事，模式数组循环匹配，最后打印一个分隔线：

```powershell
$patterns = @('真实公司名','同事姓名','内网IP段','行业专属词',
              '真实凭证','敏感路径')
foreach ($p in $patterns) {
    $m = Select-String -Path $file -Pattern $p -AllMatches
    if ($m) { Write-Output "HIT: $p" }
}
Write-Output "=== done ==="
```

输出里只看到 `=== done ===` 才算通过。清单里写得很重：**grep 0 匹配是硬门槛，不是参考**。有 HIT 就回去改，不带敏感词推送。

### 关二：发布配置，未来日期直接 404

frontmatter 有两个不写进任何教程的坑。

第一个是日期。`date` 写成未来时刻，Hugo 会把这篇判定为「未来稿」——不进 public 目录，本地构建正常、不报错、没有任何提示，线上就是 404。表象是「文章发出去却打不开」，你翻遍部署日志什么都找不到，因为构建环节它压根没把这篇算进去。所以红线写死：**date 只能取当前时刻或更早**。

第二个是编码。frontmatter 必须是 UTF-8 无 BOM——带 BOM 的文件，解析器把 BOM 当成正文第一个字符，frontmatter 整块失效。落盘不用编辑器另存，用一行明确的写入：

```powershell
[IO.File]::WriteAllText($dst, $text, (New-Object Text.UTF8Encoding $false))
```

`$false` 就是无 BOM。这类坑的共同点是：**出错的地方和看见症状的地方隔着一条部署链路**，本地永远一切正常。

### 关三：构建自检，裸围栏的正则冤案

代码块必须带语言标记，这条规则本身没争议，争议在判据。最早配的尺子是一把正则，匹配「一行恰好只有三个反引号」，命中一次算一次违规。全仓跑出来 1,777 行，报告写着「大量代码块缺语言标记」。

手动翻被判不合格的文章，发现每个代码块都规规矩矩带着标记。那 1,777 行是什么？是**收围栏**——代码块结束的那个光秃秃的 ` ``` `。markdown 规范只要求开围栏带标记，收围栏本来就该是裸的。那把正则不区分开栏和收栏，把全仓代码块总数的一半数成了违规。

修法是扔掉正则，换状态机：closed 态遇到围栏线是开栏，info string 为空才计一次真违规；open 态遇到围栏线一律是收栏，不检查。现在的放行门槛是一条命令：

```text
RESULT: FENCE_LINT = 篇=1 / 开围栏=9 / 缺标记=0
```

缺标记 = 0，才准进推送。这事的教训不在围栏，在判据本身：**数字尺子错了，比形容词更隐蔽——形容词错了你还会怀疑它，数字错了，人人都会先去怪活。**

### 关四：推送，忘加代理就超时

这个博客仓库托管在 GitHub，网络环境决定了 push 必须走本地代理：

```powershell
git -c http.proxy=http://127.0.0.1:10809 push origin main
```

不带代理的 push 会挂到超时才失败，而且报错表象像网络抖动，没有任何提示指向代理。第一次踩的时候重试了两次，第二次才想起来是环境问题。所以这条也进了红线：push 必走代理，失败别盲试，加 `-c http.proxy` 重跑。

顺带一条：这个仓库只推 main。主干分支命名上有过几次摇摆，现在固定 main，禁推别的——少一个分支，少一类「推错地方」的事故。

### 关五：部署验证，等 1-2 分钟再 curl

push 成功不等于线上可访问。托管平台的自动构建有 1-2 分钟延迟，这个窗口里 curl 到 404 不代表失败，只代表部署还没完成。所以验收动作的定义是「**等待后的实跑**」：

```powershell
(Invoke-WebRequest -Uri "https://www.plbear.com/posts/<slug>/" `
    -UseBasicParsing).StatusCode
```

要的是状态码原文，不是「应该已经好了」。部署链路里有 CDN 缓存、有构建队列，任何一环都可能慢——「立即 200」不是验收标准，「重试后 200」才是。

## 钉在终点之后，两件事自动发生

### 中间判据自己长出来了

验收在终点，意味着中间每一关必须留下**可机检的产物**——否则任务卡在半路时，你没法定位它卡在哪。于是每道关都长出了自己的判据：

| 关卡 | 判据 | 出处 |
|---|---|---|
| 脱敏 | grep 0 匹配 | 泄底事故 |
| 发布配置 | date ≤ 当前、无 BOM | 未来稿 404 |
| 构建自检 | 缺标记 = 0 | 1,777 行冤案 |
| 推送 | 远端出现 commit | 代理超时 |
| 部署验证 | 实跑 200 | 部署延迟误判 |

这些判据没有一条是开会讨论出来的。验收标准改一次，判据清单就长一截——因为验收在终点逼着每一关「自证通过」，而自证的方式只能是一段可执行的检查。

### 断点第一次可见

字数验收下，一篇稿子可以卡在任何地方而报表全绿，因为报表只看字数。HTTP 200 验收下，断点直接可见：卡在脱敏，是本地文件还没过 grep；卡在配置，是 frontmatter 有字段没落；卡在推送，是远端没有 commit；卡在部署，是 commit 到了但 curl 404。

每一关都有明确的产物形态，缺哪个产物，就是卡在哪关。断点可见之后，「催进度」这个词就消失了——你不需要催任何人，只需要看最后一件产物停在哪。

## 产能数字换了一个计量单位

产能底线每周 ≥2 篇，量纲从「字数」换成了「200 的个数」。

这个改动的深处在注水难度。字数可以注水：复制一篇旧文改两行，三千字就到手了，报表照涨。200 注不了水——要骗过一次 curl，得走完脱敏、配置、构建、推送、部署整条链路，一步都省不掉。**验收标准钉在终点，等于把整条链路变成了必经之路。**

周报里的句子也跟着变了。以前写「本周产出 3 篇、1.2 万字」；现在写「本周上线 2 篇：URL A 返回 200、URL B 返回 200」。前者是工作量证明，后者是交付证明。

## 收尾：三条能带走的规矩

1. **验收标准定在哪一环，交付物就停在哪一环。** 想要线上可访问，就把验收钉在 curl 200 上；钉在字数上，你只会得到字数。
2. **每道关都要留下可机检的产物。** 验收在终点，中间的断点就必须靠产物定位；没有产物的关卡，是静默失败的温床。
3. **交付物必须是外部可观测的状态。** 本地文件、本地构建、本地自测通过，都不算交付；只有外部能观测到的状态——公网 URL、别人的系统、真实用户——才算交付。

写完这篇的时候，下一篇文章的验收标准已经写好了：线上 URL 实跑 200，贴出状态码原文。至于字数？一个字都没提。
