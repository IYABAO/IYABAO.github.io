# AI 应用架构模式：从单体 Prompt 到分层系统

"AI 应用不就是调 API 吗，要什么架构？"——这是把 AI 应用当"脚本"的想法。当应用复杂到一定程度（多 Agent、多工具、多数据源、商业化），**没有架构的 AI 应用必然失控**。

这篇文章是 AI 应用的分层架构模式：交互层、编排层、能力层、数据层，以及从单体 Prompt 到分层系统的演进路径。

## 一、AI 应用的"架构"指什么

```
传统应用架构：模块划分、依赖管理、可测试、可扩展
AI 应用架构：多了两个维度——
  1. 模型交互（Prompt/上下文/工具调用怎么组织）
  2. 不确定性（输出不可控，要校验/降级/重试）
```

**AI 架构的核心目标**：**把不确定性关进笼子**——让"概率性输出"的失控面可控。

## 二、四层架构

```
┌─ 交互层（用户怎么用）
│    ├─ 对话 / 表单 / 流式渲染
│    └─ 意图捕获（问题、指令、语音）
│
├─ 编排层（AI 怎么想）
│    ├─ 状态机 / 多 Agent / 工具调用循环
│    ├─ 上下文管理（压缩/记忆）
│    └─ 评测与降级（回答校验/重试）
│
├─ 能力层（AI 能干什么）
│    ├─ 工具（MCP / Function Calling）
│    ├─ 检索（RAG / 向量）
│    └─ 生成（模型路由 / 提示词模板）
│
└─ 数据层（AI 基于什么）
     ├─ 业务数据（结构化/实时）
     ├─ 知识库（文档/向量）
     └─ 反馈数据（评估/优化）
```

**关键原则**：**层与层之间通过"结构化接口"通信**（编排层传状态对象，能力层返 JSON）——和传统分层架构一样，目的是可替换、可测试。

## 三、演进路径：从单体到分层

### 阶段 1：单体 Prompt（Demo 期）

```
一个 Prompt 干所有事：对话 + 工具 + 状态全在上下文里
适用：验证想法（能跑就行）
问题：改一处全崩、不可测、不可扩展
```

### 阶段 2：分层化（产品期）

```
交互层/编排层/能力层/数据层拆开
适用：产品要稳定
关键：状态从 Prompt 里拿出来（进状态机/工作记忆）
```

### 阶段 3：服务化（规模化）

```
每层独立服务：
  编排服务（会话状态机）
  能力服务（工具/MCP）
  数据服务（检索）
适用：多端/多场景/商业化
```

## 四、各层的关键模式

### 交互层

```
✅ 流式渲染（首字即出）
✅ 结构化输入（意图明确）
✅ 错误友好（AI 出错时给"重试/换说法"引导）
```

### 编排层（核心）

```
✅ 状态机（流程锁死，越级 = 事故）
✅ 上下文管理（压缩 + 记忆 + 事实抽取）
✅ 工具调用循环（最大轮数 + 审计）
✅ 校验-重试（回答不过校验 → 重写/降级）
```

### 能力层

```
✅ 工具定义规范（名称/描述/参数——LLM 的说明书）
✅ 模型路由（简单任务快模型，复杂任务强模型）
✅ 检索与生成解耦（RAG 是能力，不是上下文）
```

### 数据层

```
✅ 业务数据实时性（工具查询 > 快照）
✅ 反馈闭环（线上差评 → 评测集 → 回归）
✅ 权限（能力层过滤，不是展示层）
```

## 五、架构决策的"非功能性"考量

| 考量 | 架构影响 |
|---|---|
| **成本** | 模型路由、语义缓存、上下文压缩（省 token） |
| **延迟** | 流式、TTFT 优化、预取 |
| **可靠性** | 重试、降级（模型挂了 → 缓存/小模型兜底） |
| **可观测** | 全量 Trace、质量评估、成本分账 |
| **安全** | 工具鉴权、数据隔离、注入防护 |

**AI 架构的验收标准**：**出问题时能定位、能降级、能止血**——不是"永远不出错"。

## 六、踩坑记录

1. **跳过阶段 2 直接服务化**：拆了 8 个服务，编排逻辑散落 → 先分层（模块内），再服务化（模块间）
2. **状态放 Prompt 不放系统**：会话状态写在系统提示词里 → 无法校验、无法恢复 → 状态放状态机/数据库
3. **能力层和编排层耦合**：工具调用逻辑写死在业务代码 → 工具走 MCP 标准化，编排只管"怎么调"
4. **没有降级路径**：模型挂了整个产品挂 → 缓存答案 / 简单规则兜底 / 明确"服务暂时不可用"

## 总结

AI 应用架构的核心认知：

1. **四层**：交互、编排、能力、数据——每层职责清晰
2. **架构的目标是把不确定性关进笼子**：校验、降级、重试、可观测
3. **演进路径**：单体 Prompt → 分层 → 服务化（别跳级）
4. **结构化接口**：层间用状态对象/JSON 通信，可替换可测试

**AI 应用成熟的标志：模型只是架构里可替换的一层**——换模型、加工具、改流程都不动整体结构。到那一天，AI 应用才真正是"应用"，不是"脚本"。
