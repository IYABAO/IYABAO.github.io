# 分布式任务调度：从 Cron 到 XXL-Job

"每天凌晨 3 点跑报表"——单机时一个 Cron 搞定。上集群后问题来了：**3 个节点都执行，报表算 3 遍**。分布式任务调度解决的就是：任务在集群里"只执行一次、可分片、可重试、可管理"。

## 一、单机 Cron 的局限

```
问题 1：重复执行（集群 3 个节点 → 任务跑 3 遍 → 数据重复/冲突）
问题 2：单点故障（执行节点挂了 → 任务丢了）
问题 3：不可管理（跑没跑、失败没有、下次什么时候）
问题 4：不可分片（大任务一个节点扛，跑几小时）
问题 5：配置要发版（改个执行时间要重新部署）
```

## 二、分布式调度的核心机制

### 1. 调度器与执行器分离

```
调度中心（Scheduler）：管"任务什么时候跑"（一台）
执行器（Executor）：管"任务怎么跑"（集群多台）

调度中心分发 → 执行器执行 → 结果回传
调度中心挂了？→ 高可用部署（多调度中心，同一时刻一个主）
```

### 2. 执行策略（防重复）

```
单机路由：任务指定一台执行（轮询/哈希/指定机器）
分片广播：任务分成 N 片，每台执行一片
失败转移：执行失败 → 换一台重试
```

### 3. 任务分片（大任务的解法）

```
数据 100 万条：
  分片数 = 节点数（4 台）→ 每台处理 25 万
  // 分片参数：index（第几片）+ total（总片数）
  // 数据按取模分片：WHERE id % 4 = 0（节点1）...

效果：4 台并行 → 耗时 /4
```

## 三、XXL-Job 实践

XXL-Job 是国内最流行的开源方案（国人开发，文档全）。

### 架构

```
调度中心（xxl-job-admin）→ 注册/心跳 ← 执行器（业务服务内置）
  │ 触发（HTTP/嵌入）
  ▼
业务任务方法
```

### 集成（Go）

```go
// 任务执行器：注册任务
func init() {
    exec := xxl.NewExecutor(
        xxl.ServerAddr("http://scheduler:8080/xxl-job-admin"),
        xxl.RegistryKey("delivery-job"),
    )
    exec.RegTask("report_daily", ReportDaily)   // 注册任务
    exec.Run()
}

// 任务方法（返回状态）
func ReportDaily(c *xxl.RunReq) string {
    // 分片处理：c.Index / c.Total
    processShard(c.Index, c.Total)
    return "success"
}
```

### 关键配置

```
调度中心：注册执行器、配 Cron 表达式、配路由策略
任务配置：
  路由策略：第一个/轮询/分片广播/故障转移
  失败重试：重试次数 + 报警
  超时时间：任务超时熔断
  阻塞策略：串行/丢弃后续/覆盖之前
```

## 四、任务设计规范

```
✅ 任务要幂等（重试不重复）——前文《接口幂等设计》的通用
✅ 任务要可重入（上次没跑完，这次怎么办 → 阻塞/丢弃策略）
✅ 大任务分片（单机超 10 分钟 → 考虑分片）
✅ 任务要有日志（每片每步，失败可查）
✅ 关键任务加告警（失败/超时/重试后仍失败）
```

## 五、踩坑记录

1. **任务不幂等**：重试跑两遍 → 数据翻倍 → 任务必须幂等（用幂等键/状态机）
2. **分片不均匀**：按 ID 取模，数据分布不均 → 用业务维度分片（按用户/按区域）
3. **执行器内存泄漏**：任务里开 goroutine 不回收 → 执行器 OOM → 任务控制并发 + 超时
4. **调度中心单点**：admin 只部署一台 → 挂了任务全停 → admin 高可用（主备）
5. **任务依赖**：报表任务依赖数据同步任务完成 → 用"任务编排"（前驱/后继）或自检（数据就绪再算）

## 六、选型对比

| 方案 | 特点 | 适用 |
|---|---|---|
| XXL-Job | 功能全、文档全、中文 | 绝大多数团队 |
| Quartz | 老牌、Java 原生 | Java 单机/简单集群 |
| Elastic-Job | 分片强（ZooKeeper） | 大规模分片任务 |
| 自研（Redis 锁+Cron） | 轻量 | 任务少、不想引框架 |
| 云服务 | 托管 | 不想运维 |

**选型建议**：任务 < 20 个且简单 → Redis 锁 + 本地 Cron 够用；任务多/要分片/要管理 → XXL-Job。

## 七、什么时候必须上调度平台

```
✅ 任务 > 10 个，管理靠猜
✅ 集群部署，任务会重复执行
✅ 有大任务要分片
✅ 任务失败需要报警/重试
✅ 执行时间要频繁调整（不想发版）
```

## 总结

分布式任务调度的核心认知：

1. **调度与执行分离**：调度中心管"何时"，执行器管"如何"
2. **三件事**：防重复（路由策略）、可分片（大任务）、可恢复（重试转移）
3. **任务本身要幂等**：调度平台再稳，任务不幂等也白搭
4. **运维三件套**：日志、告警、超时熔断

**定时任务是最容易"静默出错"的系统**：没人盯着它，错了也是半夜错。有了调度平台 + 日志告警，任务才从"玄学"变成"可管理"。
