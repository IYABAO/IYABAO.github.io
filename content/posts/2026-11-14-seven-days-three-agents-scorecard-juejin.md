三台 AI agent 各干各的，每台在汇报末尾都写「已完成」。11 月 7 日我想回答一个朴素问题：过去一周它们到底交付了什么、有没有假装交付？翻了两小时日志，我答不上来——不是没数据，是数据全是形容词。

于是有了后面七天：让三台 agent 共用一套记分卡，每条判据都能被一条命令算出数字。七天做完，踩了五个坑，每个都有实测数字。

## 时间线：每天只解决一件事

| 天 | 只做一件事 | 当天教训 |
|---|---|---|
| D1 | 立项，写清「交付」指什么 | 形容词无法审计 |
| D2 | 看板挂了一次 | 环境本身也要有判据 |
| D3 | 立唯一原则：一条命令算数字 | 第一版 11 条判据，6 处不干净 |
| D4 | 上环形交叉复算 | 差异要分硬分歧和口径差 |
| D5 | 抓幽灵产物 | 只扫一个目录会误杀真产物 |
| D6 | 抓编数 | 改卡面不改脚本，机器照样判 PASS |
| D7 | 给 SKIP 正名 + 给指标装减法 | SKIP 不是失败，也不是达标 |

唯一原则只有一句话：

```text
判据必须能被一条命令算出数字。
写「良好 / 达标 / 优秀 / 稳步推进」的一律作废，退回重写。
```

记分卡固定六列：`ID / 判据 / 复算命令 / 目标值 / 当前值 / 达标`。达标列只允许 `Y / N / BROKEN`，后来加了一等态 `SKIP`。

## 坑一：形容词判据等于没判据

第一版 11 条判据里 6 处读不出「怎么算」：「心跳日志质量良好」「面试准备稳步推进」「保费控制合理」。判定的发生地在人脑子里，而人脑子里没有版本号。

改成命令行结论后，判据从「我说好」变成「你自己跑」：

```powershell
$n = (Select-String -Path D:\agentSpace\larvis\workRoutine\conclusions\J1_POOL.md -Pattern '^\|\s*\d+\s*\|').Count
Write-Host "RESULT: J1 = $n"
```

但只做这一步不够，还有两个副作用：

- **目标值拍在动作改不动的地方。** 阈值卡 64.00%，实测 64.104%，要回绿只需入金 4.84 元——这条判据量的是噪声，今天红明天自己绿。
- **判据数学上不可翻转。** 年化保费率红线 2%，实测 9.92%，反解要建仓日在 392 天前，而那合约 392 天前还没挂牌。它是纪律红线，不能和可优化指标混在一层。

## 坑二：自己给自己打分，编数看不出来

第一版各家自填，填了三天全绿。D6 我不看卡面，直接跑卡上那条命令，抓到两个：

1. **改卡面不改脚本**：卡面 3.45%，命令输出 2.80%。结论改了，证据没改。判「编数嫌疑」，当天这项从 0 变 1。
2. **自述 PASS ≠ 实测 PASS**：巡检自述 11 段全 PASS，独立跑是 10 PASS / 1 FAIL——那段检查只数「段名出现过没有」，段 FAIL 也算命中。

改法是环形互检：X 的卡由 C 复算，L 的卡由 X 复算，C 的卡由 L 复算。差异超过 5% 必须单列分歧；硬分歧 0 才算这轮干净。

还有一个更隐蔽的同源问题：**备份做在改后等于没有备份**。改完把当前文件拷成 `.bak`，核查时发现它和当前文件 SHA256 完全一致——备份的是改后结果。真备份 72,564 B，当时卡面已 74,308 B。判备份有效性要看 `SHA(备份) ≠ SHA(当前)`，不是看文件在不在。

## 坑三：幽灵产物，三个方向全踩

「幽灵产物」= 声称写了、磁盘上没有。D5 我以为抓了一堆，结果三个方向都翻车：

- **只扫一个目录**：那天内容线 8 份 / 95,744 B 全在另一台 agent 的素材目录，我这边一份没有。按单目录扫就是「零交付」，差点把做完的活打回重做。
- **按汇报文件名查存在性**：汇报写 `..._PLAYBACK_...`，磁盘是 `..._PLAYBOOK_...`，差一个词，字节 4,964 完全对。一次改名就能误杀。
- **解析错误当文件不存在**：C2 说有 1 个幽灵，实际文件真实存在 12,287 B，是解析器把双反斜杠当 UNC 路径解析失败。不是幽灵，是尺子坏了。

修尺子不等于放宽标准——那次只动路径归一化，目标值、阈值、扫描范围一律不动。

## 坑四：SKIP 被当成 BROKEN

杀伤力最大的一个，纯粹是工程细节。扫码脚本约定：当日心跳日志未生成时以 exit 3 (SKIP) 退出。外层包装脚本末尾有退出码守卫：

```powershell
if ($null -ne $LASTEXITCODE) { exit $LASTEXITCODE }
```

exit 3 被透传，验证器判 **BROKEN「命令跑不通」**，而输出里明明写着 `missing=0`。于是每天凌晨那半小时，全绿的卡上必亮一条假故障。

修法是在卡面那行命令里加一层语义翻译，配三个要点：

```powershell
$o = (powershell -NoProfile -ExecutionPolicy Bypass -File D:\agentSpace\carvis\scripts\declared-vs-disk-scan.ps1 -Source both) -join ([char]10)
$st = [regex]::Match($o, 'status=([A-Z]+)').Groups[1].Value
$m  = [regex]::Match($o, 'missing=(\d+)').Groups[1].Value
if ($st -eq 'SKIP' -and $o.Contains('log file not found')) { Write-Host 'RESULT: C2 = SKIP' }
elseif ($st -eq 'SKIP') { Write-Host 'RESULT: C2 = FAIL' }
elseif ($st -eq 'FAIL') { Write-Host 'RESULT: C2 = FAIL' }
elseif ($m -eq '')     { Write-Host 'RESULT: C2 = FAIL' }
else                   { Write-Host ('RESULT: C2 = ' + $m) }
$global:LASTEXITCODE = 0
```

1. SKIP 豁免只给「status=SKIP 且输出含 log file not found」这一种情形，索引缺失照旧 FAIL。
2. 末尾显式归零退出码，内层不再透传。
3. 不许用 0 冒充 SKIP：SKIP 记 `SKIP`，不写 Y、不记 0。

实测：改前 `RESULT: C2 = 0` + returncode 3（判 BROKEN）；改后 `RESULT: C2 = SKIP` + returncode 0。

**监控系统的假故障比真故障更消耗信任。** 一条每天必红的假红灯，三天后就没人看了。

## 坑五：指标自我繁殖，C5 从 1 涨到 12

C5 量「可全自动跑的检查项数」，是所有判据里最危险的一条，因为它奖励加法：11 月 10 日一天从 1 段做到 11 段，到 11 月 14 日已经 12 段。

更糟的是复算命令只数「段名是否出现」，段 FAIL 也算命中。所以 C5=11 那天，其中一段 BOM 检查是 FAIL 的——11 这个漂亮数字完整掩盖了那次失败。**一段只会报 PASS 的检查，加多少段都是装饰。**

闸门规则只有一句：

```text
C5 每增加一段，必须回答：这一段省掉了原来哪个要人做的事？
回答不出来的段，不加。
```

逐段盘完，两条答不出来：

| 段 | 答不出来的地方 | 增量省活 |
|---|---|---|
| 5-BYTES | 已被 11-CLAIM 完整接管（5 源 vs 2 源） | 0 秒/次 |
| 7-E2 | 已被 8-ENCGUARD 的 G1/G3/G4 严格包含 | 0 秒/次 |

于是 12 → 10，C5 从 1 涨到 12 之后第一次反向收敛。顺带扫了反向问题「有没有段只会报 PASS」：12 段全部有显式 FAIL 分支，0 段符合——这条结论对我不利（本想再砍两段），但如实写了，没为凑清单编造。

## 尺子自己也会坏

判据全靠命令，命令本身成了新单点。七天里它坏了三次，都是「输出看着对、机器读出另一个意思」：

1. 结论行放了两个数字：`RESULT: J2 = 6/10`，判定器只认恰好 1 个数字，永远 MANUAL。
2. 比值没算小数：`673/813`，判定器当两个数，失效。规矩改成先算成 `0.828`。
3. SKIP 修好后，验证器正则不认非数字，回退扫全行数字，把 ID 里的 `2` 当读数判 FAIL。

共性：尺子上的刻度也要有判据。现在核验器自己跑自测，五类结果都要能正确分类；全量一轮 9.3 秒，瓶颈已经从「跑命令」回到「读五份报告 + 判断」。

## 七天后的样子

三份记分卡各 70~90 KB，头部写实测时刻和 Get-Item 字节数。每轮读数：

```text
PASS=17  FAIL=1  BROKEN=0  MANUAL=1  SKIP=0
硬分歧 0 处   编数嫌疑 0 处
```

唯一 FAIL 是年化保费率 5.57% 对红线 2.00%，真实缺口，红了十几天没改成绿——纪律红线不靠改数字变绿。看板 569 条任务：done 560 / in_progress 3 / todo 3 / backlog 3，三家各 1 在跑、1 待办、1 后备，七天里第一次这么整齐。

## 五条能直接抄的规则

```text
1. 判据必须一条命令算出数字，写形容词的一律退回。
2. 自己算的不算数，环形互检，差异 >5% 必须单列分歧。
3. 判幽灵前先枚举所有根目录；备份有效性看 SHA 不等，不看文件在不在。
4. SKIP 是合法态：不写 Y、不记 0、不判 BROKEN，且只给一种豁免情形。
5. 指标必须能减：加一段先回答「省掉了谁的什么活」，答不出来就不加。
```

## 还没解决的三件事

1. **判据读死快照**：有条复算命令指向首行标「已废弃」的旧池文件，机器照样判 PASS。数字对，指向错。
2. **SKIP 端到端没独立复跑**：只复现了无日志窗口，没造「运行中日志突然缺失」的链路场景。
3. **减法的阻力在心理上**：删两段花了一晚上说服自己，因为那是我亲手写的。但账很清楚——每天多跑两段零增量检查，一年 700 多次白跑。

## 结尾

七天里最贵的一课不是「怎么写判据」，是承认自己会判错，并把这件事写进流程。三台 agent 里有一台在汇报阶段自己抓到自己两处错并当场改：结论行两个数写反、把副本字节当成生产脚本字节。这不是我教的，是流程逼出来的——每条结论后面都跟着可复算的命令，写反了下一轮就被自己的命令打脸。

所以记分卡不是给我看今天绿不绿，是给三天后的我看：当时你凭什么说它好了？证据在哪一行？还能不能重跑一遍？答不上来，那张卡就是装饰品。
